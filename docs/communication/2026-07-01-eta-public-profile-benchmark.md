# ETA赛事公开资料与荣誉榜单合规拆解

日期：2026-07-01

## 目的

本文件记录对「运动纪 / ETA赛事」小程序公开界面的竞品拆解，用于 FOPEN 后续版本评估是否从“匿名公开榜单”升级为“球员公开资料 + 授权展示”的产品结构。

本次分析只基于公开可见界面、用户提供截图、Computer Use 可见窗口和微信官方公开文档。不解包、不抓包、不复制第三方小程序代码。

### 首页结构

首页品牌为「ETA赛事」，不是单纯榜单页。它把公开身份展示放在赛事平台体系内：

- 核心入口：联盟介绍、ETRS介绍、赛事品牌、商务合作、个人战绩、个人奖项、荣誉榜单、M豆商城。
- 底部 Tab：ETA赛事、活动、场馆、生涯、我的。
- 首页赛事卡片展示报名状态、赛事名称、积分级别、项目、场馆、时间、报名入口。

### 荣誉榜单结构

点击「荣誉榜单」后先出现榜单选择器，不是直接进入单一排行榜。

「球员榜」包括：

- 冠军榜
- 胜率榜
- 等级榜
- 积分榜
- 活跃榜
- 财富榜

「品牌榜」包括：

- 新锐品牌
- 热门品牌

这个结构说明它把榜单解释为赛事平台的荣誉/竞技记录体系，而不是微信用户资料展示页。

### 积分榜观察

积分榜当前展示：

- 年榜/月榜切换。
- 总榜/单打/双打切换。
- 全国、性别、年度筛选。
- TOP500 排名提示。
- 字段：排名、球员、ETA积分。
- 球员列展示头像、昵称/匿名名、性别角标。

关键事实：

- 第一名展示为「[匿名用户]」并使用默认插画头像。
- 其他用户混合展示自定义头像、默认 M 标识、昵称和性别角标。
- 无法从界面判断头像是否来自微信头像、平台上传头像或平台默认头像。

### 冠军榜观察

冠军榜当前展示：

- 年榜/月榜切换。
- 总榜/单打/双打切换。
- 全国、性别、年度筛选。
- TOP500 排名提示。
- 字段：排名、球员、冠军数。
- 冠军数同时展示冠军和亚军数量。

关键事实：

- 「[匿名用户]」同样出现在冠军榜。
- 公开昵称、头像和性别角标只对部分用户展示。
- 匿名状态不是积分榜的偶发现象，而是榜单体系通用状态。

### 匿名用户主页阻断

点击冠军榜里的「[匿名用户]」后，小程序提示“不可查看匿名用户主页”。

这点非常重要：它不只是把公开名称替换成匿名，还阻断了匿名用户的公开主页访问。也就是说，匿名状态至少影响：

- 榜单昵称。
- 榜单头像。
- 公开主页入口。

### 非匿名公开球员主页

点击非匿名用户头像后，可进入公开球员主页和奖项荣誉页。

公开球员主页可见：

- 头像。
- 昵称。
- ETRS 等级。
- 赛季总积分。
- 赛季排名。
- 参赛总数。
- 对战场数。
- 冠亚军数。
- 场胜率。
- 赛事记录。

奖项荣誉页可见：

- 头像。
- 昵称。
- 奖项总数。
- 全部/冠军/亚军筛选。
- 奖项卡片和赛事时间。

结论：它确实存在公开球员档案，但与匿名状态联动。匿名用户不只是换默认头像，而是无法查看主页。

### 系统设置与隐私设置

「我的」页进入「系统设置」后，可见：

- 账号及安全。
- 资料编辑。
- 隐私设置。
- 微信授权。
- 用户须知。
- 隐私协议。

「隐私设置」内存在细粒度对外展示控制：

- 荣誉榜单：冠军榜、胜率榜、等级榜、积分榜、活跃榜、财富榜，右侧说明为关闭排名显示。
- 赛事生涯：参赛站数、冠亚军数、对战场数、场胜率、赛事记录、奖杯展示，右侧说明为关闭将不对外显示。

这说明竞品公开头像昵称的关键合规支撑并不是“别人也展示头像”，而是：

- 有平台账号体系。
- 有公开球员主页。
- 有匿名用户状态。
- 有榜单/生涯逐项隐私开关。
- 匿名状态能阻断公开主页。

### 仍未验证或不能下结论的点

- 未点击头像上传入口，避免触发相册/头像选择授权；因此不能确认它使用微信 `chooseAvatar` 还是普通图片上传。
- 未修改任何隐私开关，因此不能确认关闭后后端是否立即匿名化、缓存是否同步清理。
- 未完整阅读或引用对方隐私政策正文，只确认「隐私协议」入口可达。
- 「账号及安全」页没有在首屏看到注销账号入口，只观察到关联账号能力和实名/公平性说明；是否在更深层仍待确认。
- 未抓包、不解包、不逆向，无法确认真实数据表结构和后端授权逻辑。

## 关键判断

ETA赛事不是简单的“排行榜显示微信头像昵称”，而是一个完整的赛事平台账号体系：

- 有赛事报名。
- 有个人战绩。
- 有个人奖项。
- 有荣誉榜单。
- 有生涯页。
- 有我的页。
- 有系统设置。
- 有隐私设置。
- 有匿名用户状态。

这类结构更容易把公开展示解释为“赛事参赛资料 / 球员公开档案 / 荣誉记录展示”，而不是直接拉取微信用户信息做公开排行榜。

对 FOPEN 来说，重要差异不是 UI 上有没有头像，而是数据和授权链路：

- 头像是否来自微信用户信息，还是用户在赛事平台内主动上传。
- 昵称是否是微信昵称，还是参赛名 / 球员名 / 赛事公开名。
- 公开展示是否是默认行为，还是用户在明确场景中单独同意。
- 是否允许撤回公开展示。
- 撤回后排行榜、赛事名单、战绩、荣誉页是否立即匿名化。
- 匿名后是否还能进入公开主页。
- 是否能按榜单和生涯字段逐项关闭对外展示。

## 官方规则边界

微信官方文档中，头像昵称属于开发者处理的信息。对应接口/组件包括：

- `<button open-type="chooseAvatar">`
- `<input type="nickname">`
- 已回收的 `wx.getUserInfo`
- 已回收的 `wx.getUserProfile`

官方“头像昵称填写”能力的定位是“完善个人资料”，并且微信会对用户上传图片和昵称做内容安全检测。这个能力解决的是“如何取得头像昵称”，不是自动授权“公开展示给其他用户”。

因此，FOPEN 不能仅因为用户能上传头像，就直接在公开排行榜展示真实头像昵称。还需要单独处理公开范围、同意、撤回和删除。

## 可借鉴的产品结构

### 1. 从“微信用户资料”改成“球员公开资料”

FOPEN 后续版本不应再把公开展示字段命名为微信头像、微信昵称或用户头像昵称。建议建立独立的球员公开资料：

- 公开球员名
- 球员头像
- 城市 / 俱乐部，选填
- 打法 / 级别，选填
- 公开展示范围

公开资料应与微信登录身份分离。OpenID 只用于账号识别，不作为公开展示依据。

### 2. 公开展示必须绑定具体场景

公开授权不能写成笼统的“同意公开资料”。应拆成明确场景：

- 排行榜展示：积分榜、胜率榜、冠军榜等。
- 周最佳 / 荣誉榜单展示。
- 赛事报名名单展示。
- 赛程 / 对阵 / 赛果展示。
- 球员个人主页展示。
- 个人生涯统计展示：参赛站数、胜率、战绩、奖杯等。

默认建议全部关闭，或至少在首次报名/首次参赛时逐项提示。

### 3. 公开资料与报名流程结合

ETA赛事首页强绑定“赛事报名 + 个人战绩 + 荣誉榜单”。FOPEN 如果要恢复头像昵称展示，应避免在独立排行榜里突然收集资料，而是在报名或完善球员资料时解释：

> 你的球员公开资料将用于赛事报名名单、赛程赛果、排行榜和荣誉记录展示。你可以随时在设置中撤回公开展示。

### 4. 给用户可见的撤回路径

设置页需要保留并强化：

- 撤回公开资料展示
- 修改球员公开资料
- 榜单/生涯逐项公开开关
- 删除账号资料
- 隐私政策
- 用户服务协议

撤回后必须做到：

- 排行榜不再返回真实头像和公开名。
- 周最佳不再返回真实头像和公开名。
- 赛事名单和赛果页不再返回真实头像和公开名。
- 公开主页不可进入，或进入后只展示匿名状态。
- 缓存清理或版本化，避免旧头像昵称继续出现。

### 5. 匿名状态要成为一等状态

ETA赛事的关键设计不是“榜单上有头像”，而是“匿名用户有明确状态”。FOPEN 后续如果恢复公开资料，建议把匿名作为一等状态设计：

- 榜单显示 `[匿名用户]` 或赛事内匿名编号。
- 使用默认头像。
- 隐藏性别、城市、打法等可识别字段。
- 阻断公开主页。
- 阻断奖项荣誉页的个人入口，或只展示不可回溯到个人的聚合记录。
- 撤回公开展示后立即切换到匿名状态。

这比单纯增加一个“是否展示头像昵称”的布尔值更稳，因为审核关注的是“是否公开用户信息”，不是某一个字段。

## FOPEN 后续版本建议方案

### 短期稳过版本

继续保持公开榜单匿名化：

- 默认头像。
- 球员编号或匿名名。
- 排名、积分、胜率、战绩可以公开。
- 不公开真实头像、微信昵称、用户上传头像。

该方案最符合当前微信驳回文案，适合作为恢复审核通过的优先路径。

### 中期试验版本

在审核恢复稳定后，新增“球员公开资料”能力，但默认不用于公开榜单：

数据模型建议：

```js
publicProfile: {
  enabled: false,
  identityMode: 'anonymous', // anonymous | public
  displayName: '',
  avatarFileID: '',
  source: 'self_upload',
  scopes: {
    ranking: false,
    weeklyStar: false,
    tournamentRoster: false,
    matchResult: false,
    honorBoard: false,
    playerHome: false,
    careerStats: false,
    awards: false
  },
  consentVersion: '',
  consentAt: null,
  revokedAt: null,
  updatedAt: null
}
```

后端返回规则：

- 未登录用户读取公开榜单时，只返回匿名身份。
- 已登录用户读取自己的资料时，可以返回私有资料。
- 只有 `publicProfile.enabled === true`、`identityMode === 'public'` 且对应 `scope === true` 时，才返回公开头像和公开名。
- 所有云函数统一走同一套 `toPublicIdentity(member, scope)` 转换函数。
- 公开主页入口也必须走同一套规则，不能只在榜单上匿名，详情页仍可通过 memberId 访问。
- 撤回公开展示后要清理本地缓存、云端榜单缓存和任何 `rank_cache` 类聚合缓存。

前端展示规则：

- `identityMode === 'anonymous'` 时，统一展示默认头像和 `[匿名用户]`。
- 匿名用户头像/昵称区域不可点击，或点击后提示“匿名用户不可查看主页”。
- 公开用户才允许进入球员主页、奖项荣誉页和生涯统计页。
- 设置页把“全部撤回”与“按场景关闭”分开，降低用户误解。

### 后续重新提审策略

不要一次性把所有公开页面恢复头像昵称。建议分阶段：

1. 先只在“我的资料”本人可见页支持上传头像。
2. 再在“报名确认页”展示本人公开资料预览。
3. 再试“赛事报名名单”展示公开资料。
4. 最后才考虑排行榜 / 荣誉榜单展示。

每一步都需要配套截图和说明材料。

## 对当前审核的影响

当前微信驳回口径已经明确指向“公开页面展示用户信息”。所以不能用“竞品也展示头像昵称”作为申诉主线。

更稳妥的申诉主线仍然是：

- 已取消公开排行榜真实头像昵称展示。
- 已停止在公开页面返回可识别用户身份。
- 排行榜、周最佳、赛事公开页均已匿名化。
- 用户资料仅在本人可见或必要管理场景使用。

ETA赛事可以作为后续产品方向参考，但不应作为当前版本继续公开展示真实头像昵称的理由。

## 对 FOPEN 的直接结论

短期：当前提审版本不要恢复公开头像昵称。审核已明确认为 FOPEN 公开榜单展示用户信息存在风险，继续保持匿名化是最稳路线。

中期：如果要做竞品类似能力，不能只恢复头像昵称；必须同时补齐四件事：

- 独立平台球员资料，不直接把微信身份当公开身份。
- 匿名状态与公开状态并存。
- 榜单、生涯、奖项、主页等场景级隐私开关。
- 后端统一按 scope 返回公开身份，撤回后所有公开入口和缓存同步匿名。

不能直接爬或复制对方代码。可以借鉴的是产品边界和合规结构：公开档案是赛事平台资料，匿名是可选且有效的状态，隐私设置能逐项控制对外展示。
